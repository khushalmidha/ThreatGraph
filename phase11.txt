## PHASE 11 — RAG + LLM SOC Analyst + MITRE Mapping



**Goal:** Evidence-grounded investigation layer on top of the detector — never the detector itself.



**Do:**

1. `rag/ingestion/`: chunk and embed a security knowledge base (MITRE ATT&CK technique descriptions, this project's own detection docs, simulated runbooks/policies, network architecture docs) into pgvector or Qdrant.

2. `rag/retrieval/`: retriever returning relevant chunks given an incident's structured evidence.

3. Provider-agnostic LLM interface (`backend/app/soc/`) with a system prompt that explicitly forbids inventing evidence and requires labeling every claim **Observed / Inferred / Recommended**.

4. MITRE ATT&CK mapping: candidate technique + confidence + evidence + related observations, never stated as fact without supporting evidence.

5. Structured investigation report generator matching the spec's format (Incident Summary, Severity, Primary Host, Likely Behavior, Confidence, Observed Evidence, Potential ATT&CK Mapping, Affected Assets, Attack Path, Recommended Actions, Containment Recommendation, Uncertainty).

6. `POST /soc/investigate/{incident_id}` and `POST /soc/query` implemented for real, grounded in retrieved evidence (test that answers change when evidence changes, and that the model won't answer confidently with no retrieved evidence).



**Acceptance checks:**

- Running an investigation on a real Phase 10 incident produces a report with every evidence claim traceable to something actually stored for that incident (no hallucinated hosts/numbers).

- Asking `POST /soc/query` a question with no supporting retrieved evidence results in an appropriately hedged/uncertain answer, not a confident fabrication.
