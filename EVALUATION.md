# ThreatGraph Technical Evaluation & Scientific Audit

This document establishes the scientific audit, reproducible benchmarks, and empirical verification for all architectural and performance claims in **ThreatGraph**.

> **CRITICAL TRANSPARENCY NOTICE**: All evaluations and benchmarks in ThreatGraph are conducted on **synthetic, simulated network security telemetry** generated by `traffic/generator.py` under controlled adversary scenarios. These results demonstrate algorithmic capabilities, spatial-temporal graph modeling, and vector search triage; they do **not** represent an enterprise SOC production benchmark or real-world network deployment.

## 2. Model Evaluation Benchmark (PR-AUC, F1, Precision, Recall)

### Metric Definitions
- **Precision**: $\frac{TP}{TP + FP}$
- **Recall**: $\frac{TP}{TP + FN}$
- **F1-Score**: $2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$
- **PR-AUC**: Area under the Precision-Recall Curve ($\int P(R) dR$), vital for class-imbalanced intrusion detection.
- **ROC-AUC**: Area under the Receiver Operating Characteristic ($\text{TPR}$ vs $\text{FPR}$).

### Dataset & Evaluation Split
- **Dataset**: Synthetic network telemetry generated via `traffic/generator.py` simulating legitimate host traffic, lateral movement (RDP/SMB), port scans, and data exfiltration.
- **Total Evaluated Events**: 5,006 events across 50 host entities.
- **Split**: 80% Train (4,005 events), 20% Test (1,001 events), stratified by time sequence with random seed `42`.
- **Class Imbalance**: 83 attack events out of 1,001 test events (**8.29% positive rate**), modeling realistic SOC telemetry skew.

### Benchmark Command
```bash
python evaluation/run_detection_benchmark.py --config configs/eval.yaml
```

## 4. Architecture Specification

### Spatial Stream (Graph Attention Network v2)
- **File**: `ml/models/gnn.py` (`TemporalGNN`)
- **Graph Construction**: Dynamic graph where nodes represent host machines and edges represent observed network flows between hosts within a 60-second sliding window.
- **Node Features ($d=16$)**: Rate of outbound connections, failed authentications, distinct ports accessed, byte volume, protocol entropy, historical risk score.
- **Edge Features ($d=4$)**: Port category (Web, SSH/RDP, DB, Other), byte count (log scale), packet count, flow duration.
- **GNN Layers**:
  - Layer 1: `GATv2Conv(in_channels=16, out_channels=32, edge_dim=4)` with multi-head attention.
  - Recurrent Temporal Update: `GRUCell(input_size=32, hidden_size=32)` updating host node state representations across discrete graph snapshots.
  - Layer 2: `GATv2Conv(in_channels=32, out_channels=32)` for 2-hop neighborhood message passing.
- **Readout / Pooling**: Global mean pooling aggregating node embeddings into graph-level representation $h_{\text{spatial}} \in \mathbb{R}^{32}$.

### Temporal Stream (Transformer Encoder)
- **File**: `ml/models/transformer.py` (`TelemetryTransformer`)
- **Input**: Sequence of host event feature vectors $X_{\text{seq}} \in \mathbb{R}^{B \times T \times 16}$ where $T=10$ consecutive flow events.
- **Encoding**: Linear projection ($16 \to 16$) + Sinusoidal positional encoding ($PE_{(pos, 2i)} = \sin(pos / 10000^{2i/d})$).
- **Encoder Architecture**: 2 Transformer encoder layers (`nn.TransformerEncoderLayer`) with `d_model=16`, `nhead=4`, `dim_feedforward=32`, and `dropout=0.1`.
- **Output Pooling**: Mean pooling across sequence dimension yielding $h_{\text{temporal}} \in \mathbb{R}^{32}$.

### Fusion & Multi-Task Prediction Heads
- **File**: `ml/models/fusion.py` (`FusionModel`)
- **Fusion Mechanism**: Concatenation of spatial graph embedding and temporal sequence embedding:
  $$h_{\text{fused}} = \text{ReLU}\left(\mathbf{W}_{\text{proj}} [h_{\text{spatial}} \,\|\, h_{\text{temporal}}] + b_{\text{proj}}\right) \in \mathbb{R}^{32}$$
- **Prediction Heads**:
  1. `threat_probability`: $\sigma(\mathbf{W}_{\text{threat}} h_{\text{fused}}) \in [0, 1]$ (Binary Cross-Entropy Loss)
  2. `anomaly_score`: $\mathbf{W}_{\text{anomaly}} h_{\text{fused}} \in \mathbb{R}$ (MSE Loss against baseline)
  3. `threat_class`: $\text{Softmax}(\mathbf{W}_{\text{class}} h_{\text{fused}}) \in \mathbb{R}^3$ (Cross-Entropy Loss over Benign, Reconnaissance, Lateral Movement)

## 5. Attack-Path Reconstruction Algorithm

- **Implementation**: `backend/app/graph/attack_path.py` (`AttackPathEngine`)
- **Graph Formulation**: Directed network topology graph $G = (V, E)$, where $V$ are host assets and $E$ are directed network communication flows.
- **Shortest Risk Path Algorithm**: Dijkstra's algorithm where edge weight inversely mirrors node threat risk:
  $$\text{weight}(u, v) = \frac{1.0}{\max(\text{risk}(v), 0.01) + 10^{-9}}$$
  Paths with higher risk nodes accumulate lower total weight, ensuring the path finder isolates the most dangerous traversal corridor.
- **Causal Temporal Ordering Constraint**: Reconstructed paths enforce strict monotonic timestamp progression ($t_{(u \to v)} \le t_{(v \to w)}$). Flows occurring prior to ingress compromise are discarded from the causal attack chain.
- **Blast Radius Analysis**: Multi-source breadth-first search (BFS) with depth ceiling $k=3$ to compute the potential collateral exposure footprint of compromised nodes.
- **Critical Asset Vulnerability Identification**: Tarjan's bridge-finding algorithm to locate articulation points whose isolation cuts off attacker access to critical database tiers.
- **Unit Test Coverage**: `tests/test_attack_path.py` (9 tests verifying deterministic chains, cycles, disconnected components, and temporal ordering).

## 6. Graph-Aware RAG Engine (FAISS + MITRE ATT&CK)

- **Implementation**: `rag/engine.py` (`GraphAwareRAGEngine`)
- **Terminology Justification**: Named **"Graph-Aware RAG"** rather than formal GraphRAG because retrieval utilizes graph-extracted entities, topological hops, and reconstructed attack paths to synthesize vector search queries over MITRE ATT&CK knowledge documents, rather than constructing a hierarchical community graph index.
- **Vector Search Index**: FAISS `IndexFlatIP` (Exact Inner Product / Cosine Similarity over L2-normalized embeddings).
- **Indexed Corpus**: 13 curated MITRE ATT&CK Enterprise techniques and incident response runbooks:
  - T1021.001 (Remote Desktop Protocol)
  - T1021.002 (SMB/Windows Admin Shares)
  - T1021.004 (SSH Lateral Movement)
  - T1059 (Command and Scripting Interpreter)
  - T1071.001 (Web Protocols C2)
  - T1071.004 (DNS Tunneling C2)
  - T1046 (Network Service Discovery)
  - T1078 (Valid Accounts Abuse)
  - T1048 (Exfiltration Over Alternative Protocol)
  - T1486 (Data Encrypted for Impact)
  - RB-001 (RDP Lateral Movement Containment Runbook)
  - RB-002 (SMB/Pass-the-Hash Isolation Runbook)
  - RB-003 (C2 DNS Exfiltration Mitigation Runbook)
- **Top-$K$ Retrieval**: Configured to $k=3$ with minimum cosine similarity threshold 0.15.
- **Query Grounding**: Graph entities (source host, destination host, port numbers, observed protocol, reconstructed path hops) are deterministically compiled into structured triage prompts.

## 7. Containment Engine (Simulated Zero-Trust Policy)

- **Implementation**: `backend/simulation/policies.py` (`SimulatedFirewall`)
- **Containment Mode**: **Simulated micro-segmentation policy engine**. Does **not** modify production kernel firewall rules, eBPF maps, or cloud security groups.
- **Trigger Conditions**:
  - Automatic isolation triggered when host risk score $\ge 80.0$ or when verified lateral movement is traced.
  - Benign hosts (risk score $< 80.0$) are strictly protected from erroneous isolation (`tests/test_containment.py::test_benign_host_not_isolated`).
- **Zone Segregation**: Maps IPs to zones (`INTERNET`, `DMZ`, `INTERNAL`, `DATABASE`) and enforces default-deny intra-zone communication during an active containment incident.
- **Rollback Support**: Complete audit trail with rollback capability (`unquarantine_host`) restoring host network access after analyst clearance.

## 8. Ingestion Pipeline & Kafka Compatibility

- **Local Benchmark Stream**: Local evaluation benchmarks and tests execute against an in-process sliding window queue backend (`HostFeatureState`), eliminating external broker overhead for reproducible evaluation.
- **Kafka Architecture Capability**: `backend/worker_detection.py` provides an asynchronous `AIOKafkaConsumer` adapter interface configured for `threat-telemetry` topic ingestion.
- **Distinction Notice**: All reported throughput figures of **3,193.80 events/sec** represent the local in-process benchmark, not distributed Kafka broker network transit latency.

## 9. Scientific Limitations & Boundaries

1. **Synthetic Telemetry Scope**: Evaluations are performed entirely on synthetic telemetry produced by a stochastic simulator. Real enterprise networks exhibit heterogeneous noise, encrypted payload obfuscation, and missing NetFlow packets not modeled here.
2. **Absence of Production SOC Benchmark**: The model has not been evaluated against real-world DARPA, CIC-IDS2017, or enterprise SOC streaming environments.
3. **No Hardware EDR Enforcement**: Zero-trust containment actions are simulated within software state tables and do not interact with production host agent sensors (e.g., CrowdStrike Falcon, Windows Defender ATP).
4. **Offline Evaluation**: The detection benchmark evaluates offline batches rather than streaming concept drift over extended multi-week deployments.
5. **Embedding Model Simplicity**: Local vector retrieval utilizes a deterministic TF-IDF / term-frequency projection onto 64 dimensions for reproducible testing without requiring external cloud LLM API tokens.
