## PHASE 9 — Attack Graph Reconstruction



**Goal:** From a suspicious host, reconstruct the propagation path.



**Do:**

1. `backend/app/graph/` (attack-path variant): given a flagged host, walk the communication graph to build source→destination edges with timestamp, evidence, confidence, risk contribution, identifying initial host, propagation path, exposed high-value assets, potential blast radius.

2. Persist to `attack_paths`. Implement `GET /incidents/{id}/attack-path`.



**Algorithmic sub-tasks (real graph DSA, driving the propagation/blast-radius logic — not decorative):**

- **Weighted shortest path (Dijkstra)**: edge weight = inverse of (confidence × risk contribution), so the "most likely propagation path" from the initial host to any downstream asset is a genuine shortest-path computation, not a hand-walked heuristic.

- **Multi-source BFS**: given a set of currently-flagged hosts, compute blast radius (all reachable hosts within the graph) in one pass instead of per-host BFS.

- **Tarjan's algorithm (articulation points / bridges)**: identify hosts/edges whose removal would disconnect the network — surfaced as "critical assets" in the attack-graph output, directly supporting the blast-radius/critical-asset story.

- **Union-Find (DSU)**: maintain connected components of the communication graph incrementally; flag when a new edge merges two previously-disconnected clusters as an additional anomaly signal fed into the risk engine.



**Acceptance checks:**

- Running a Phase 2 lateral-movement or ransomware-like scenario produces a non-trivial multi-hop attack path with evidence on every edge.

- The shortest-path attack path is provably optimal for the given edge weights (test against a small hand-built graph fixture with a known answer).

- Articulation-point detection correctly flags a known critical host in a hand-built fixture graph (e.g. a single gateway host connecting two subnets).
